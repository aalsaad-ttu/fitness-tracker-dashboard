# Reflection

## Decisions

One of the biggest decisions I made during this project was to keep the scope focused on a simple calorie and protein tracking dashboard instead of trying to build a much larger application with accounts, databases, or advanced backend systems. Early in the project, I realized that it would be more valuable to create a smaller project that worked well rather than a larger project with unfinished or broken features. I also decided to focus heavily on usability and responsiveness so the site would work on both desktop and mobile devices.

Another important decision was to build the project using plain HTML, CSS, and JavaScript instead of introducing frameworks or libraries. Since this was my first larger web project, I wanted to strengthen my understanding of the fundamentals before adding additional complexity. This approach also made deployment through GitHub Pages simple and reliable.

## What worked

The interactive features ended up working very well. The meal tracking system, calorie totals, protein tracking, delete buttons, and local storage all function correctly and make the project feel like a real application instead of just a static webpage. I am also satisfied with the visual improvement from the first version of the project to the final MVP. The layout became cleaner, more organized, and more responsive across different devices.

The deployment process through GitHub Pages also worked well once I became comfortable with it. At the beginning, I was unsure about how deployments and commits connected to the live website, but after practicing throughout the project, it became much easier and more natural.

## What I would do differently

If I were starting over, I would spend more time planning the structure and features of the project before writing code. Early on, I changed the layout and feature ideas multiple times, which created extra work. A more detailed plan from the start would have helped me avoid reworking parts of the project later.

I would also start using a local development environment like VS Code earlier instead of relying mostly on editing directly through GitHub. While GitHub editing worked fine initially, the project eventually became large enough that a dedicated code editor would have made development faster and more organized.

## What I learned

This project taught me a lot about how real web projects are built step by step. I learned how HTML, CSS, and JavaScript work together to create interactive experiences instead of static pages. I also learned how important responsiveness and usability are when designing for different devices.

Another major thing I learned was how deployment works. Before this class, I had very little experience with GitHub Pages or pushing updates to a live site. Now I understand the workflow of editing files, committing changes, pushing updates, and verifying that those updates appear on the deployed project.

I also learned that building for the web is not just about writing code. Planning, organization, iteration, and managing scope are just as important. There were several times where I wanted to add more advanced features, but I learned that keeping the project focused and functional leads to a much stronger final result.
